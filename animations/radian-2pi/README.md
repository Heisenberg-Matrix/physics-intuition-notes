# 谁规定一圈必须是 360°？

一条 175 秒的竖屏动画，配中文配音与字幕。它不从“一弧度等于多少度”的定义出发，而是先把“一圈记成几份”还原成一个可以随手改的选择：360 只是习惯，改成 4 份、100 份、1 份，照样能记录转了多少；任意角度都可以写成“转过的圈数”。随后出现一个新需求——量一段弧有多长——逼着我们把“转过的圈数”换算成长度。换算式里自然冒出一个系数 `2π/N`；把 `N` 选成 `2π`，系数正好是 1，公式只剩 `s = rθ`。同一个数字 `θ`，从此既能记录旋转，又能直接给出弧长。π 在这里始终是周长与直径的比，不是角度；`θ = s/r` 是两个长度之比，不是长度本身。

## 叙事顺序

1. **一圈为什么是 360°？** 一整圈、`360°`、一个玫红框，加一句“谁规定的？”。把同一圈依次记成 4 份、`360°`、1、100、10、1，最后停在 1；只有中央的数字在变，圆的几何不动——数值换了，旋转一点没丢。再用 0.40 圈、`1/4 圈 = 0.25`、任意的 0.37 圈说明：任意角度都能用“转过的圈数”表示。整圈记作 1 时，角度数值就等于圈数。
2. **新需求：这段弧有多长？** 圆周上高亮一段弧，打个问号，并留出约两秒的视觉停顿。把上、下两个半圆拉直成两条线段，每条长 `πr`，合起来 `C = 2πr`；再退回定义 `π = C/d`，明确 π 是比值。
3. **把圈数换成长度。** 弧长 = 整圈周长 × 转过的圈数。规定整圈对应 N、实际角度是 θ，则圈数 = θ/N，于是 `s = 2πr · θ/N`。用 N = 4、θ = 1 的例子走一遍（刻度只是示意，N 不必是整数），把式子整理成 `s = (2π/N) · r · θ`，玫红框只框住系数。
4. **让系数消失。** 先只把系数框出来，问一句“能不能让这个系数变成 1？”，不提前给出答案。再把问题变成方程：`2π/N = 1`，所以一圈 = `2π`。系数原地变成 1；1 和它右边的乘号一起消失，`r · θ` 顺势贴回等号后面，式子只剩 `s = rθ`。随后补一句“θ 改用新标尺：整圈 = 2π”，说明换的是角度单位，弧本身没有变。
5. **半径当软尺。** 蓝色的 r 弯到圆周上，弧长正好等于 r 时，`θ = 1 弧度`；2r、3r 依次是 2、3 弧度；量的是弧段，不是直弦。让 θ 连续转，r、θ、s 三个读数同屏变化。
6. **一石二鸟。** 同一个 θ 放在画面中央，两条虚线分别接到“记录旋转”和“计算弧长”两块面板：左边是 `θ = 1.20 rad`，右边是 `s = rθ = 1.20 r`——同一个 1.20，一个数字，两种用途。`θ = s/r` 出现时明确标注：两个长度之比，没有长度单位；弧度是角度单位，不是米、厘米。
7. **为什么偏偏是 2π？** 整圈弧长是 `2πr`，代进 `θ = s/r`，补上 `= 2π`；半圈 `π`，四分之一圈 `π/2`。再补一层来源：π 本来是周长与直径之比，是我们选了“弧长 ÷ 半径”，它才进入角度值。
8. **收束。** `360° = 2π 弧度`，`s = rθ`，一个数字，两种用途——这就是弧度制。

python -m http.server 8123

## 渲染

依赖：Python 3.10+、Manim CE 0.19.1、NumPy、edge-tts 7.3.1（配音，需联网）、FFmpeg（写 MP4 与混音）。本仓库已在 Manim 0.19.1 + Python 3.10.11 + edge-tts 7.3.1 下验证。

```bash
cd animations/radian-2pi
pip install -r requirements.txt

./run.sh preview     # 540×960 @30，输出 media/preview.mp4（含配音）
./run.sh             # 1080×1920 @30，输出 radian-2pi.mp4 与 poster.jpg（含配音）
```

等价的 Manim 命令：

```bash
# 低清预览（无声）
PREVIEW=1 python -m manim -ql --disable_caching scene.py RadianScene

# 成片（Manim 按画面高度命名输出目录，竖屏 1080×1920 是 1920p30）
python -m manim -qh --disable_caching scene.py RadianScene

# 只渲染前 N 段，用来逐段检查版面（STAGE=3 表示只渲染 intro/need/formula）
STAGE=3 PREVIEW=1 python -m manim -ql --disable_caching scene.py RadianScene

# 配音：逐句合成，命中缓存后不再联网
python narration.py

# 把音轨混进视频
ffmpeg -i media/videos/scene/1920p30/RadianScene.mp4 \
  -i media/voice/voiceover.wav -map 0:v:0 -map 1:a:0 -c:v copy \
  -af loudnorm=I=-16:TP=-1.5:LRA=11 -c:a aac -b:a 128k -ar 48000 -ac 1 \
  -movflags +faststart -shortest radian-2pi.mp4
```

`--disable_caching` 建议保留：本片大量使用 `always_redraw`，分段缓存不能完整记录 updater 状态，复用旧分段容易出现错帧。

## 配音

- **音色**：`zh-CN-XiaoxiaoNeural`，语速 `+4%`；逐句合成后用 20 ms 淡入淡出拼进 175 秒音轨。
- **字幕与语音分开写**：`CUES` 是给眼睛看的，保留 `π`、`θ`、`s = 2πr × θ/N` 这些符号；`NARRATION` 是同一句话的口语版，“派”“西塔”“二派 r”。两条文案按 cue key 一一对应，`narration.py` 直接用 `NARRATION`，`PRONOUNCE` 只在符号漏网时兜底。
- **对齐**：`ONSETS` 记录每句字幕实际淡入完成的秒数（取自 `scene.py` 的 `[cue]` 日志）；语音从该时刻起播，若上一句还没说完就顺延，保证不重叠。本片 34 句全部准点起播（顺延 0.00 秒），最长的停顿留在“让系数等于 1”的问句之后。
- **响度**：混流时 `loudnorm=I=-16:TP=-1.5`，符合短视频平台常见的 −16 LUFS 目标。
- **缓存**：每句 MP3 按文本哈希缓存在 `media/voice/`，改一句只会重合成那一句；首次合成需联网。
- **无背景音乐**：只保留人声，避免和关键词字幕抢注意力。

## 实现要点

- **先有问题，再有定义**：前 95 秒完全不出现“弧度”两个字。先让 360° 变成一个可替换的约定，再制造“量弧长”的需求，最后才让 2π 作为最优选择出现。片尾才说出“弧度制”。
- **数字先于定义**：S1 让同一圈依次记成 `360°`、1、100、10、1，只有中央数字在换，圆的几何不动；再用 0.40、`1/4 圈 = 0.25`、0.37 圈说明任意角度都能写成圈数。整圈记作 1 时，“角度数值 = 圈数”自然成立。
- **换算式是推出来的，不是背的**：`s = 2πr · θ/N` 的每一项都对应画面上已有的东西——`2πr` 是拉直后的整圈，`θ/N` 是转过的圈数。系数 `2π/N` 用玫红框单独框住，`N = 2π` 的动机就变成“让系数等于 1”。
- **让 1 自然消失**：S4 把 `s = (2π/N) · r · θ` 拆成四块；系数先原地变成 `1`，再让 `1` 和它右边的乘号一起淡出，`r · θ` 左移贴回等号后，最后才收成 `s = rθ`。不是整行淡出再淡入。
- **半径真的当尺子量**：橙色弧段沿圆周生长，长度严格等于蓝色半径（`θ = 1` 时弧长 = r，几何精确，不是近似）。2 弧度、3 弧度处各留一道刻度，外侧标 `r`、`2r`、`3r`；玫红虚线画出同一段的直弦，强调“量的是弧段”。
- **圆周拉直**：把上、下半圆分别形变成两条水平线段，端点顺序与圆弧一致（上半圆从右走到左，下半圆从左回到右），否则形变过程中会在空中打一个圈。两条线各标 `πr`，合起来正好 `2πr`。
- **连续量**：`ValueTracker` 保存弧度，弧段、半径、读数都用 `always_redraw` 跟随；`Arc` 的组件数与角度无关，逐帧重建不会触发 `IndexError`。读数用自定义 `LiveNumber`——本机没有 LaTeX，`DecimalNumber` 的默认 `MathTex` 会报错，`Text` 版 `become` 又会把数字挪到原点，所以先把新 `Text` 移到旧位置再 `become`。
- **弧线不用 `Arc(angle=2π)`**：整圈用四段 `Arc(angle=π/2)` 拼成，贝塞尔闭合的那条“整圆”会留下一个巨大的缺口。
- **颜色分工**：青绿 `#299C8D` 是角度 θ 与旋转，橙黄 `#D6A04D` 是弧长 s 与长度，蓝 `#648BCB` 是半径 r，玫红 `#C67591` 是 π、系数与强调。字幕、公式、图形用同一套颜色，观众不用读文字也能对上号。
- **安全区**：所有公式与字幕限制在竖屏中央约 7.2–7.3 个画幅单位内（左右各留约 8% 空白）；主体圆心固定在 `(0, 1.90)`，全片不切镜头。
- **字幕不压公式**：字幕单独一条，固定在 `y = −6.55`；公式带依次排在中部，每段只留当前需要的一两行，旧行先淡出再进新行。
- **标签不叠**：动径上的 `θ` 与 N = 4 示例的 `θ = 1` 同角、只差 0.23 个半径，叠在一起会让等号多出一道横线；示例开始时先淡出动径标签，只留一个 θ。
- **时间轴**：`hold_until()` 把每个画面锁在预定节拍上；`until(key)` 直接读取下一句字幕的名义时刻，画面与字幕共用 `CUES` 一份时间表，避免两处时间走散。`cue()` 记录字幕真实淡入时刻（日志里的 `[cue] ...` 就是 `ONSETS` 的来源）；`STAGE` 环境变量可只渲染前几段，方便逐段检查版面。

## 验证情况

- **渲染**：Manim 0.19.1 完整渲染 540×960@30 预览与 1080×1920@30 成片，单场景连续渲染，时长 175.00 秒；`./run.sh preview` 与 `./run.sh` 均已跑通。
- **数学**：`θ = 1` 时橙色弧段长度与蓝色半径严格相等（`Arc` 半径不变、角度为 1 rad）；`θ = 2`、`θ = 3` 对应 2r、3r；整圈 `θ = 2π`、半圈 `π`、四分之一 `π/2` 与弧长 `2πr`、`πr`、`πr/2` 一一对应。π 只以 `C/d` 的身份出现，没有写成角度；`θ = s/r` 被明确标为两个长度之比，并注明“没有长度单位”；弧度被说明为角度单位，不是米、厘米。
- **逻辑链**：一圈的数值（S1）→ 圈数表示任意角（S1）→ 量弧长的需求（S2）→ 圈数 = θ/N（S3）→ 系数 `2π/N`（S3）→ 令系数为 1 得 N = 2π（S4）→ `s = rθ`（S4）→ 一个数字两种用途（S5）→ 整圈代入得 2π 与 π 的来源（S6）→ 收束（S7）。S4-1 只提出“能不能等于 1”，不提前出现 N = 2π。
- **逐帧抽查**：S1-4A 的数字轮换不改变圆的几何；N = 4 实例中刻度、θ 标记与“四分之一圈”同屏；系数框只框住 `(2π/N)`，`1` 与乘号消失后 `s = rθ` 干净居中；`θ = s/r` 与两行说明不重叠；分屏左面板为 `θ = 1.20 rad`、右面板为 `s = 1.20 r`，虚线连接不断开；S6 的两行来源说明与半圈、四分之一圈等式不重叠；片尾三行公式与“弧度制”落版不重叠。
- **安全边距**：540×960 与 1080×1920 下最左/最右内容均留有约 8% 画幅宽度；字幕与公式不重叠。
- **配音**：34 句按字幕时刻起播，互不重叠，全部准点（顺延 0.00 秒）。首句 0.80 秒起声，末句 172.24 秒收尾，片尾留约 2.8 秒静默定格。
- **响度**：成片实测 −16.2 LUFS、真峰值 −1.2 dBTP、LRA 5.3 LU（目标 −16 LUFS / −1.5 dBTP）。
- **已知限制**：本机无 LaTeX，公式字形为 Cambria Math；Edge TTS 首次合成需要联网，没有背景音乐。
