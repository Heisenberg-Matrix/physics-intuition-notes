# 谁规定一圈必须是 360°？

一条 115 秒的竖屏动画，配中文配音与字幕。它不从“一弧度等于多少度”的定义出发，而是先把“一圈记成几份”还原成一个可以随手改的选择：360 只是习惯，改成 4 份、1 份，照样能记录转了多少。随后出现一个新需求——量一段弧有多长——逼着我们把“转过的圈数”换算成长度。换算式里自然冒出一个系数 `2π/N`；把 `N` 选成 `2π`，系数正好是 1，公式只剩 `s = rθ`。同一个数字 `θ`，从此既能记录旋转，又能直接给出弧长。π 在这里始终是周长与直径的比，不是角度；`θ = s/r` 是两个长度之比，不是长度本身。

## 叙事顺序

1. **一圈为什么是 360°？** 一整圈、`360°`、一个玫红框，加一句“谁规定的？”。把同一圈改记成 4 份、1 份，半径照样转，圈数照样数——数字换了，旋转一点没丢。
2. **新需求：这段弧有多长？** 圆周上高亮一段弧，打个问号。把上、下两个半圆拉直成两条线段，每条长 `πr`，合起来 `C = 2πr`；再退回定义 `π = C/d`，明确 π 是比值。
3. **把圈数换成长度。** 弧长 = 整圈周长 × 转过的圈数。一圈分成 N 份、转过 θ 份，则圈数 = θ/N，于是 `s = 2πr · θ/N`。用 N = 4、θ = 1 的例子走一遍，把式子整理成 `s = (2π/N) · r · θ`，玫红框只框住系数。
4. **让系数消失。** N 是我们自己定的，那就令 `2π/N = 1`，即一圈 = `2π` 份。系数变成 1，式子只剩 `s = rθ`。
5. **半径当软尺。** 蓝色的 r 弯到圆周上，弧长正好等于 r 时，`θ = 1 弧度`；2r、3r 依次是 2、3 弧度；量的是弧段，不是直弦。让 θ 连续转，r、θ、s 三个读数同屏变化。
6. **一石二鸟。** 同一个 θ 放在画面中央，两条虚线分别接到“记录旋转”和“计算弧长”两块面板：一个数字，两种用途。
7. **为什么偏偏是 2π？** 整圈弧长是 `2πr`，除以 r 得 `θ = 2π`；半圈 `π`，四分之一圈 `π/2`。π 自始至终是两个长度之比。
8. **收束。** `360° = 2π 弧度`，`s = rθ`，一个数字，两种用途——这就是弧度制。

成片：[radian-2pi.mp4](radian-2pi.mp4)（1080×1920，30 fps，115 秒，AAC 48 kHz 单声道配音）。

## 预览

直接用浏览器打开 [index.html](index.html)，或在仓库根目录启动静态服务器：

```bash
python -m http.server 8123
# http://localhost:8123/animations/radian-2pi/
```

## 渲染

依赖：Python 3.10+、Manim CE 0.19.1、NumPy、edge-tts 7.3.1（配音，需联网）、FFmpeg（写 MP4 与混音）。本仓库已在 Manim 0.19.1 + Python 3.10.11 + edge-tts 7.3.1 下验证。

```bash
cd animations/radian-2pi
pip install -r requirements.txt

./run.sh preview     # 540×960 @30，输出 media/preview.mp4（含配音）
./run.sh             # 1080×1920 @30，输出 radian-2pi.mp4 与 poster.jpg（含配音）
```

等价的 Manim 命令：

```bash
# 低清预览（无声）
PREVIEW=1 python -m manim -ql --disable_caching scene.py RadianScene

# 成片（Manim 按画面高度命名输出目录，竖屏 1080×1920 是 1920p30）
python -m manim -qh --disable_caching scene.py RadianScene

# 只渲染前 N 段，用来逐段检查版面（STAGE=3 表示只渲染 intro/need/formula）
STAGE=3 PREVIEW=1 python -m manim -ql --disable_caching scene.py RadianScene

# 配音：逐句合成，命中缓存后不再联网
python narration.py

# 把音轨混进视频
ffmpeg -i media/videos/scene/1920p30/RadianScene.mp4 \
  -i media/voice/voiceover.wav -map 0:v:0 -map 1:a:0 -c:v copy \
  -af loudnorm=I=-16:TP=-1.5:LRA=11 -c:a aac -b:a 128k -ar 48000 -ac 1 \
  -movflags +faststart -shortest radian-2pi.mp4
```

`--disable_caching` 建议保留：本片大量使用 `always_redraw`，分段缓存不能完整记录 updater 状态，复用旧分段容易出现错帧。

## 配音

- **音色**：`zh-CN-XiaoxiaoNeural`，语速 `+4%`；逐句合成后用 20 ms 淡入淡出拼进 115 秒音轨。
- **字幕与语音分开写**：`CUES` 是给眼睛看的，保留 `π`、`θ`、`s = 2πr × θ/N` 这些符号；`NARRATION` 是同一句话的口语版，“派”“西塔”“二派 r”。两条文案按 cue key 一一对应，`narration.py` 直接用 `NARRATION`，`PRONOUNCE` 只在符号漏网时兜底。
- **对齐**：`ONSETS` 记录每句字幕实际淡入完成的秒数（取自 `scene.py` 的 `[cue]` 日志）；语音从该时刻起播，若上一句还没说完就顺延，保证不重叠。本片 28 句最多顺延 0.02 秒，等于准点。
- **响度**：混流时 `loudnorm=I=-16:TP=-1.5`，符合短视频平台常见的 −16 LUFS 目标。
- **缓存**：每句 MP3 按文本哈希缓存在 `media/voice/`，改一句只会重合成那一句；首次合成需联网。
- **无背景音乐**：只保留人声，避免和关键词字幕抢注意力。

## 实现要点

- **先有问题，再有定义**：前 35 秒完全不出现“弧度”两个字。先让 360° 变成一个可替换的约定，再制造“量弧长”的需求，最后才让 2π 作为最优选择出现。片尾才说出“弧度制”。
- **换算式是推出来的，不是背的**：`s = 2πr · θ/N` 的每一项都对应画面上已有的东西——`2πr` 是拉直后的整圈，`θ/N` 是转过的圈数。系数 `2π/N` 用玫红框单独框住，`N = 2π` 的动机就变成“让系数等于 1”。
- **半径真的当尺子量**：橙色弧段沿圆周生长，长度严格等于蓝色半径（`θ = 1` 时弧长 = r，几何精确，不是近似）。2 弧度、3 弧度处各留一道刻度，外侧标 `r`、`2r`、`3r`；玫红虚线画出同一段的直弦，强调“量的是弧段”。
- **圆周拉直**：把上、下半圆分别形变成两条水平线段，端点顺序与圆弧一致（上半圆从右走到左，下半圆从左回到右），否则形变过程中会在空中打一个圈。两条线各标 `πr`，合起来正好 `2πr`。
- **连续量**：`ValueTracker` 保存弧度，弧段、半径、读数都用 `always_redraw` 跟随；`Arc` 的组件数与角度无关，逐帧重建不会触发 `IndexError`。读数用自定义 `LiveNumber`——本机没有 LaTeX，`DecimalNumber` 的默认 `MathTex` 会报错，`Text` 版 `become` 又会把数字挪到原点，所以先把新 `Text` 移到旧位置再 `become`。
- **弧线不用 `Arc(angle=2π)`**：整圈用四段 `Arc(angle=π/2)` 拼成，贝塞尔闭合的那条“整圆”会留下一个巨大的缺口。
- **颜色分工**：青绿 `#299C8D` 是角度 θ 与旋转，橙黄 `#D6A04D` 是弧长 s 与长度，蓝 `#648BCB` 是半径 r，玫红 `#C67591` 是 π、系数与强调。字幕、公式、图形用同一套颜色，观众不用读文字也能对上号。
- **安全区**：所有公式与字幕限制在竖屏中央约 7.2–7.3 个画幅单位内（左右各留约 8% 空白）；主体圆心固定在 `(0, 1.90)`，全片不切镜头。
- **字幕不压公式**：字幕单独一条，固定在 `y = −6.55`；公式带依次排在中部，每段只留当前需要的一两行，旧行先淡出再进新行。
- **标签不叠**：动径上的 `θ` 与 N = 4 示例的 `θ = 1` 同角、只差 0.23 个半径，叠在一起会让等号多出一道横线；示例开始时先淡出动径标签，只留一个 θ。
- **时间轴**：`hold_until()` 把每个画面锁在预定节拍上，`cue()` 记录字幕真实淡入时刻（日志里的 `[cue] ...` 就是 `ONSETS` 的来源）；`STAGE` 环境变量可只渲染前几段，方便逐段检查版面。

## 可调参数

| 参数 | 位置 | 值 / 说明 |
| --- | --- | --- |
| `PREVIEW` | 环境变量 | `1` → 540×960@30；否则 1080×1920@30 |
| `STAGE` | 环境变量 | 只渲染前 N 段（1–7），用于分段检查 |

| `ONSETS` | `narration.py` | 字幕实际淡入时刻；重跑渲染后按 `[cue]` 日志更新 |
| `TEAL` / `ORANGE` / `BLUE` / `ROSE` | `scene.py` | θ / s / r / π 的语义色 |
| `SUB_Y` | `scene.py` | 字幕高度 −6.55 |

## 验证情况

- **渲染**：Manim 0.19.1 完整渲染 540×960@30 预览与 1080×1920@30 成片，单场景连续渲染，时长 115.00 秒；`./run.sh preview` 与 `./run.sh` 均已跑通。
- **数学**：`θ = 1` 时橙色弧段长度与蓝色半径严格相等（`Arc` 半径不变、角度为 1 rad）；`θ = 2`、`θ = 3` 对应 2r、3r；整圈 `θ = 2π`、半圈 `π`、四分之一 `π/2` 与弧长 `2πr`、`πr`、`πr/2` 一一对应。π 只以 `C/d` 的身份出现，没有写成角度；`θ = s/r` 被明确标为两个长度之比。
- **逐帧抽查**：拉直段的两条线段端点顺序正确，形变过程不打圈；N = 4 实例中刻度、θ 标记与“四分之一圈”同屏；系数框只框住 `(2π/N)`；半径弯成弧后“弧长 = r”的引线与圆不相交；分屏面板与中央 θ 徽标的虚线连接不断开；片尾三行公式与“弧度制”落版不重叠。
- **安全边距**：540×960 与 1080×1920 下最左/最右内容均留有约 8% 画幅宽度；字幕与公式不重叠。
- **配音**：28 句按字幕时刻起播，互不重叠；最多顺延 0.02 秒。首句约 0.60 秒起声，末句约 113.14 秒收尾，片尾留约 1.8 秒静默定格。
- **响度**：成片实测 −16.1 LUFS、真峰值 −1.5 dBTP（目标 −16 LUFS / −1.5 dBTP）。
- **已知限制**：本机无 LaTeX，公式字形为 Cambria Math；Edge TTS 首次合成需要联网，没有背景音乐。
