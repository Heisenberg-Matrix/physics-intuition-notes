# 高轨低速大周期，为什么根本不用背？

一条约 92 秒的竖屏动画，配中文配音、同步字幕和很轻的合成背景音乐。它不把“高轨低速大周期”当口诀来念，而是把这句话拆成三个可以直接看见的物理事实：

1. 同一位置，引力加速度与卫星质量无关：`a = GM/r²`；
2. 轨道越高，`r` 越大，加速度越小；
3. 匀速圆周运动还要求 `a = v²/r`。两个 `a` 是同一个加速度，于是 `GM/r² = v²/r`，解出 `v = √(GM/r)`。

最后让两颗卫星按真实比例同时起跑：低轨跑完一圈时，高轨只走了约 35%。高轨路程更长、速度更慢，周期自然更大。片尾回到开场的选择题，答案不是被告知，而是已经被推出来了。

## 叙事顺序

1. **先制造“我背过，但不确定”的瞬间。** 像考试选择题一样给出 A“高轨低速大周期？”和 B“高轨高速小周期？”，停一拍，不公布答案。
2. **给出承诺。** 两个选项退场，地球和两条同心轨道出现；“其实，只要理解加速度。”这句承诺把记忆题改写成推导题。
3. **先排除质量。** 两颗质量不同（`m`、`2m`）的卫星放在同一半径上，加速度箭头一样长；`a = GM/r²` 里根本没有卫星质量。
4. **再看高度。** 橙色卫星从低轨半径处沿同一条径向线外移到 `2r`，画面标注“只变半径（示意）”；半径翻倍的过程中，橙色加速度箭头从与蓝色等长连续缩到四分之一，旁边标 `a/4`。这不是变轨动画，只是在改半径这个参数。
5. **停在关键疑问上。** “加速度小，速度就一定小吗？”先不打字幕解释，留半秒；再把视线引到圆周运动本身：速度沿切线、加速度沿半径，`a = v²/r`。
6. **让两个加速度合流。** 左边引力加速度 `GM/r²`，右边圆周运动加速度 `v²/r`，两张关系卡移到中央合成 `GM/r² = v²/r`；两边乘 `r`、开方，得到带框的 `v = √(GM/r)`。公式缩到角落，两颗卫星开始按真实速度比例运动。
7. **用同一段时间比较周期。** 两颗卫星回到同一径向起点同时出发；低轨 4 秒跑完一圈，高轨只走了约 35%。路程更长、速度更慢，所以周期更大；再写 `T = 2πr/v` 和 `T₂/T₁ = 2√2`。
8. **口诀回归。** 回到开场的选择题，圈出“高轨低速大周期”，让错误选项淡出；三行关系把推导链收拢，最后只留“理解了，就不用背了。”

## 渲染

依赖：Python 3.10+、Manim CE 0.19.1、NumPy、edge-tts 7.3.1（配音，需联网）、FFmpeg（写 MP4 与混音）。本仓库已在 Manim 0.19.1 + Python 3.10.11 + edge-tts 7.3.1 下验证。

```bash
cd animations/orbit-speed-period
pip install -r requirements.txt

./run.sh preview     # 540×960 @30，输出 media/preview.mp4（含配音与音乐）
./run.sh             # 1080×1920 @30，输出 orbit-speed-period.mp4 与 poster.jpg
```

等价的 Manim 命令：

```bash
# 低清预览（无声）
PREVIEW=1 python -m manim -ql --disable_caching scene.py OrbitScene

# 成片（Manim 按画面高度命名输出目录，竖屏 1080×1920 是 1920p30）
python -m manim -qh --disable_caching scene.py OrbitScene

# 只渲染前 N 段，用来逐段检查版面（STAGE=3 表示只渲染 intro/promise/mass）
STAGE=3 PREVIEW=1 python -m manim -ql --disable_caching scene.py OrbitScene

# 配音：逐句合成，命中缓存后不再联网
python narration.py

# 合成轻音乐
python music.py

# 把配音、音乐混进视频
ffmpeg -i media/videos/scene/1920p30/OrbitScene.mp4 \
  -i media/voice/voiceover.wav -i media/music.wav \
  -filter_complex "[1:a]volume=1.0[voice];[2:a]volume=0.45[music];[voice][music]amix=inputs=2:duration=first:normalize=0,loudnorm=I=-16:TP=-1.5:LRA=11[a]" \
  -map 0:v:0 -map "[a]" -c:v copy \
  -c:a aac -b:a 128k -ar 48000 -ac 1 \
  -movflags +faststart -shortest orbit-speed-period.mp4
```

`--disable_caching` 建议保留：本片大量使用 `always_redraw` 和由 `ValueTracker` 驱动的轨道运动，分段缓存不能完整记录 updater 状态，复用旧分段容易出现错帧。

## 物理约定与准确比例

- 中心天体球对称；卫星只受引力，忽略阻力、摄动和其他天体；轨道为稳定的匀速圆周运动。
- 所有速度、加速度和周期都在中心天体的惯性系里描述；轨道半径从**天体中心**量起，不是从地表算高度。
- 同一半径处，不同质量的卫星引力加速度相同；`a = GM/r²` 中不出现卫星质量 `m`。
- 加速度始终指向圆心；速度始终沿轨道切线。画面中的 `a`、`v` 箭头方向按这个约定画，不把径向运动伪装成轨道转移。
- 两个加速度相等的前提被明确写出：卫星做匀速圆周运动，所需向心加速度就是引力加速度，因此 `a = GM/r²` 与 `a = v²/r` 描述的是同一个 `a`。
- 取 `r₂ = 2r₁`，精确比例是：

  ```text
  v₂/v₁ = 1/√2
  T₂/T₁ = 2√2
  ω₂/ω₁ = 1/(2√2)
  ```

- 动画中取低轨周期 `T₁ = 4.0 s`，因此 `ω₁ = 2π/4`，`ω₂ = ω₁/(2√2)`。低轨跑完一圈的 4.0 秒里，高轨转过 `1/(2√2) ≈ 0.3536` 圈，约 35.4%，与 `T₂/T₁ = 2√2` 完全一致。
- 第 04 段橙色卫星沿同一条径向线从 `r` 移到 `2r`，只用于对照“半径变大、加速度按平方变小”，画面直接标注“只变半径（示意）”；没有画推进、速度方向或转移弧线，不表示真实变轨。真正的同时起跑比较放在第 07 段。

## 配音与音乐

- **音色**：`zh-CN-XiaoxiaoNeural`，语速 `+4%`；16 句逐句合成，首尾 20 ms 淡入淡出后按字幕时刻铺进 92 秒音轨。
- **字幕与语音分开写**：`CUES` 是给眼睛看的短句，刻意避开公式，把画面中部留给箭头、半径和等式；`NARRATION` 是同一句话的口语版，`GM`、`√` 等符号的读法在 `PRONOUNCE` 里兜底。两条文案按 cue key 一一对应。
- **对齐**：`ONSETS` 记录每句字幕实际淡入完成的秒数（取自 `scene.py` 的 `[cue]` 日志）；语音从该时刻起播，若上一句还没说完就顺延，保证不重叠。本片 16 句全部准点起播（顺延 0.00 秒）。
- **音乐**：`music.py` 用正弦波合成 A 小调 → F → C → G 的四小节暖色垫底，每小节 8 秒；每 4 秒一次很轻的拨弦，在“解出速度”和“给出周期公式”两处各加一声轻铃。没有使用外部采样素材。
- **混音**：人声原音量，音乐衰减到 0.45，再统一 `loudnorm=I=-16:TP=-1.5:LRA=11`；音乐始终压在人声下面，不抢关键词。
- **缓存**：每句 MP3 按文本哈希缓存在 `media/voice/`，改一句只会重合成那一句；首次合成需联网。

## 实现要点

- **先问题，后答案**：开场只提出 A/B，不在第 01 段公布答案；正确答案要到第 08 段才回来圈出。中间所有画面都在为它提供可检查的依据。
- **质量先出局**：第 03 段两颗卫星质量不同但半径相同，箭头一样长；`m`、`2m` 标签先消失，再让两条箭头合并成一条——不是用文字说“无关”，而是让画面把质量这个变量删掉。
- **半径的平方真的按平方缩**：第 04 段用同一个 `ValueTracker` 同时驱动橙色卫星的半径、虚线半径和箭头长度；箭头长度严格取 `(R1/r)²`，所以 `r` 从 `R1` 拉到 `2R1` 时，箭头从 1.0 连续缩到 0.25，不是直接换一张图。画面标注“只变半径（示意）”，避免把径向对照误读成真实变轨。
- **疑问处留白**：第 05 段“加速度小，速度就一定小吗？”出现后先停半秒，才切到单颗卫星的切向 `v` 与径向 `a`；`a = v²/r` 里的 `r` 正好解释“为什么加速度小不自动等于速度小”。
- **等式不是贴上去的**：第 06 段先让两张关系卡从左右移到中央，标题退场，等号补上；再把 `GM/r² = v²/r` 顺序变成 `GM/r = v²`、`v = √(GM/r)`。每一步只改变一行，旧行完全淡出后新行才出现，避免公式叠影。
- **真实比例的同时起跑**：第 07 段把两颗卫星的角度重置到同一径向起点，用 `ValueTracker` 驱动 `always_redraw` 卫星与 `TracedPath` 轨迹；低轨角速度 `2π/4`，高轨严格是它的 `1/(2√2)`。4.0 秒后低轨轨迹闭合，高轨只留约 35% 的橙色弧段。
- **公式与字幕分层**：字幕固定在底部单行；公式、关系卡和注释放在画面中部。每段最多保留当前需要的一两行，旧内容先退场，避免竖屏中部拥挤。
- **颜色分工**：低轨蓝 `#5E8FC7`、高轨橙 `#D9924E`、加速度青绿 `#2F9E8F`、速度玫红 `#C2647F`、关键结论玫瑰 `#C67591`。图形、箭头、公式和字幕使用同一套语义色。
- **不使用 LaTeX**：本机没有 LaTeX，公式用 Cambria Math 的 `MarkupText` 排字，中文用 Microsoft YaHei 的 `Text`；中英文不混进同一个 `MarkupText`。由于上下标会让 `TransformMatchingShapes` 分出很多碎片，公式改写采用受控的逐行淡出/淡入，并插入“两边乘 r”作为中间步骤。
- **安全区**：主体圆心固定在 `(0, 1.85)`，轨道最大半径 3.1；公式与字幕限制在竖屏中央约 7.2 个画幅单位内，左右各留约 8% 空白。
- **时间轴**：`hold_until()` 把画面锁在预定节拍上；`cue()` 记录字幕实际淡入时刻（日志里的 `[cue] ...` 就是 `ONSETS` 的来源）；`STAGE` 环境变量可只渲染前几段。

## 验证情况

- **渲染**：Manim 0.19.1 完整渲染 540×960@30 预览与 1080×1920@30 成片，单场景连续渲染，时长 92.00 秒；`./run.sh preview` 与 `./run.sh` 均已跑通。
- **物理**：`a = GM/r²` 不含卫星质量；同一半径处 `m`、`2m` 的加速度箭头等长；第 04 段橙色卫星沿径向从 `R1` 移到 `2R1` 时，箭头长度严格取 `(R1/r)²`，从 1.0 缩到 0.25；画面注明这是“只变半径（示意）”，不是变轨。`GM/r² = v²/r` 的等式前提被明确写成“两个加速度是同一个”；解得 `v = √(GM/r)`；由 `v = 2πr/T` 得 `T = 2πr/v`。取 `r₂ = 2r₁` 时 `v₂/v₁ = 1/√2`、`T₂/T₁ = 2√2`、`ω₂/ω₁ = 1/(2√2)`。
- **运动比例**：第 07 段两颗卫星从同一径向起点同时出发，低轨用 4.0 秒走完 `2π`，高轨只走 `2π/(2√2) ≈ 0.3536` 圈；画面轨迹长度与角度严格对应，不是分别摆拍。
- **逻辑链**：质量无关 → 同一位置 `a` 相同 → 高度增加 `a` 减小 → 圆周运动要求 `a = v²/r` → 两式相等 → `v = √(GM/r)` → 同时间比较高轨走得少 → `T` 更大 → 回到“高轨低速大周期”。开场不公布答案，片尾才回收。
- **逐帧抽查**：开场 A/B 不同时出现；地球圆心与轨道同心；`m`、`2m` 标签不压箭头；第 04 段“只变半径（示意）”在运动期间可见，橙色半径到 `2r` 时箭头正好缩成低轨箭头的四分之一；`r`、`2r`、`a/4` 标签分居切线两侧；单卫星段的 `v`、`a` 箭头一切向一径向；公式 `a = GM/r²`、`a = v²/r`、`v = √(GM/r)`、`T = 2πr/v` 均无缺字或叠影；第 07 段低轨轨迹闭合、高轨弧段停在大约 35%；片尾“理解了，就不用背了。”完整落在安全区内。
- **安全边距**：540×960 与 1080×1920 下最左/最右内容均留有约 8% 画幅宽度；字幕与公式不重叠。
- **配音**：16 句按字幕时刻起播，互不重叠，全部准点（顺延 0.00 秒）。首句 0.80 秒起声，最后一句“高轨低速大周期……”在 88.61 秒收尾，片尾留约 3.4 秒定格。
- **响度**：成片实测 −16.3 LUFS、真峰值 −1.4 dBTP、LRA 6.9 LU（AAC 编码后比混音滤镜目标 −1.5 dBTP 高 0.1 dB）。
- **已知限制**：本机无 LaTeX，公式字形为 Cambria Math；Edge TTS 首次合成需要联网；背景音乐是合成的极简垫底，不是完整配乐。
